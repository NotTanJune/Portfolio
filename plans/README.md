## Findings considered and rejected

- **Inline loader shell in `index.html`** (selected by the owner, rejected after vetting): `App.css` sets the page background and loads as a render-blocking stylesheet in `<head>`, so first paint already has the right background before JS. Showing the "0%" counter before JS would need a script to skip it for returning visitors, and CSP `scriptSrc 'self'` blocks inline scripts. A shell without that script would flash "0%" to every returning visitor. Revisit only if the loader is ever removed.
- **Splitting gsap out of `main.js`**: Home needs gsap and framer-motion as soon as it renders, so moving gsap to a lazy chunk gives almost no first-load gain.
- **Disabling production sourcemaps**: `.map` files are never downloaded by visitors; no load-time effect.
- **Re-encoding `projects/*` thumbnails**: lazy-loaded and below the fold or on another route; low leverage for first load.
